Embedded Local Server Suite

Host FTP, FTPS, HTTP, and HTTPS file servers directly from Android using a persistent dataSync foreground service with live client monitoring and one-tap disconnect.

  • HTTP & HTTPS Web UI: Built-in browser file manager with login sessions, range requests (206), multipart upload, rename, mkdir, and batch delete.
  • FTPS & FTP Servers: Sandboxed filesystem supporting both local storage paths and SAF DocumentFile trees with per-user permissions.
  • Brute-Force Protection: HTTP/HTTPS auth locks out after 5 failed attempts with a 30-second 429 Too Many Requests cooldown.
  • Safe Defaults: Servers are disabled until started and bind strictly to LAN IPv4 + loopback unless opted out.

Multi-Protocol Remote Storage Client

Connect to remote servers, NAS appliances, and cloud-hosted WebDAV endpoints with saved encrypted profiles, quick-connect URIs, and strict cryptographic trust verification.

  • SFTP (SSHv2): Password or PEM private key (+ passphrase) authentication with Room-backed known_hosts SHA-256 verification.
  • FTPS: Explicit & Implicit TLS with TOFU SHA-256 certificate pinning in TrustedCertDao.
  • WebDAV: HTTP/HTTPS PROPFIND, MKCOL, MOVE, DELETE, ranged downloads, Basic & Digest auth.
  • SMB: SMB 2.02–3.1.1 default dialect via jCIFS-NG; legacy SMB1 disabled unless explicitly opted in and allowed by MDM.

How It Works

Practical workflows from tap to transfer.

Three core journeys implemented across Portly’s 7 top-level navigation destinations.

1. Share Files via Browser

Open Servers, pick your root folder (internal storage or SAF tree), and start the HTTPS Server (:8443). Any desktop or mobile browser on your LAN can authenticate, browse, stream, and upload files securely.

2. Connect to NAS or Server

Open Connect or enter a quick-connect URI on Home (e.g., sftp://, smb://, ftps://). Verify the host key or TLS fingerprint once via TOFU pinning, then browse in Files.

3. Audit & Export Diagnostics

Review every transfer and server event in History with configurable 7 / 30 / 90-day retention, or export a LogRedactor-sanitized JSON diagnostic bundle from Settings.

Security & Privacy Architecture

Engineered around strict trust boundaries.

Every security control below is directly implemented in core-security, core-common, and app_restrictions.xml.

Credential & Storage Hardening

  • AndroidKeyStore AES-256-GCM: Passwords, SSH private keys, and server credentials are stored as ciphertexts in Room CredentialVault.
  • No Cloud Backups: Manifest sets android:allowBackup="false" and android:usesCleartextTraffic="false".
  • PathValidator: Canonicalizes all server paths and ZIP entries, blocking null bytes, .. escapes, and symlinks outside the root.
  • Biometric Gate: Optional or MDM-enforced BiometricPrompt unlock at app launch and server settings changes.

Enterprise MDM Managed Configurations

IT administrators can enforce policies via Android RestrictionsManager (app/src/main/res/xml/app_restrictions.xml):

  • disable_plain_ftp — Blocks starting unencrypted FTP servers.
  • disable_smb1_legacy — Locks SMB1 off; enforces SMB 2.02–3.1.1.
  • allow_public_server_bind — Forces LAN/loopback-only server binding.
  • require_biometric_lock — Mandates biometric/device credential lock.
  • disable_servers & diagnostic_logging_enabled — Controls server availability and audit logging.
